# Italiano Flow：词汇与阅读重构设计

- 日期：2026-09-19
- 状态：已完成口头设计确认，等待书面规格复核
- 目标仓库：`chenpihuamei/italiano-flow`
- 目标发布：GitHub Pages，移动端优先，可安装 PWA

## 1. 产品目标

Italiano Flow 从包含多种学习入口的综合 Demo，收缩为一个只解决两件事的学习工具：

1. 通过可追溯、可关联、可反复变式练习的词汇系统，扩大 A1–C2 意大利语词汇能力；首版内容集中服务用户当前约 B1–B2、目标 B2–C1 的需求。
2. 通过使用已学词汇编排的阅读材料和类似 IELTS 思路的阅读理解题，把“认识单词”转化为语境理解、指代解析、逻辑推断和职场表达能力。

首版以用户本人为主要学习对象，同时保持公开链接可供朋友独立使用。不同设备之间不共享进度，不建立账号系统。

## 2. 设计原则

### 2.1 学习原则

- 单词不是孤立翻面卡，而是由词义、词形、搭配、短语、词族、近义词、形近词和完整例句组成的词汇节点。
- 每天至少让学习者在语境中接触 20 个目标词或固定搭配。
- 新词先学习最高频、最常用的意义和搭配，再逐步开放专业、口语、地区或低频意义。
- 同一词在不同结构中的意义变化必须被明确训练，例如 `sodo / lavorare sodo / al sodo`、`tenere / tenere a / tenere conto di`。
- 形态变化只训练真实、自然、语义成立的时态、语气和语态；不为覆盖语法表而制造不自然句子。
- 阅读前不显示生词释义，防止把阅读理解退化成查词练习；提交后才展示证据、同义替换和关联词汇。

### 2.2 产品原则

- 首页首先提供一个明显的“开始练习”按钮，不用先选择题型。
- 题型只能在“设置”中启用或关闭，训练过程中不能临时挑选简单题型。
- CEFR 等级 A1–C2 可在设置中选择；诊断完成后可接受系统推荐等级，也可手动覆盖。
- 所有个人学习数据只保存在当前浏览器；公共 GitHub 仓库只保存共享内容。
- 所有等级、释义、例句和版权信息必须能追溯到版本和来源，不能制造虚假的精确度。
- 意大利语作为测试和训练的主要界面语言；中文只用于答题后的解释和诊断报告。

## 3. 范围

### 3.1 本次重构包含

- 自适应词汇诊断测试。
- A1–C2 分级词库；首版共 600 个词汇节点，重点为 B2–C1。
- 词汇练习队列和多题型训练。
- 18 篇首版分级阅读材料及阅读理解题。
- 已学词、错题、短语三个可检索集合。
- 词根词缀、词族、近义词、反义词、形近词、易混词和固定搭配之间的双向导航。
- 设备本地学习记录、错题记录、诊断历史和设置。
- 内容版权状态、来源信息和公开构建检查。
- 从当前 `localStorage` 数据迁移到 IndexedDB，尽量保留已有训练记录。

### 3.2 删除

- `Risorse` / 资源页。
- `Sottotitoli` / 字幕页。
- `Progressi` / 独立进度页。
- 与词汇和阅读无直接关系的首页入口。

学习统计不会消失，而是分别进入首页摘要、词库筛选和每次练习结果，不再保留单独的“Progressi”模块。

### 3.3 本次不包含

- 用户账号、云数据库、好友排行榜或跨设备同步。
- 服务器端 AI 实时生成题目。
- 自动抓取或重新发布付费教材、Netflix 字幕、整篇新闻或其他未经许可的版权内容。
- 以第一次诊断结果宣称用户获得正式 CEFR 证书。
- 基于尚不存在的大规模答题数据伪装成科学 IRT 校准。

## 4. 信息架构

底部主导航只保留四个入口：

1. **训练**：默认首页。
2. **阅读**：推荐文章、分级筛选和阅读历史。
3. **词库**：已学词、错题、短语三个分页。
4. **设置**：等级、题型、每日目标、语言辅助和数据管理。

### 4.1 训练首页

首屏内容按优先级排列：

1. 大型主按钮：`Inizia l'allenamento`。
2. 今日目标：目标 20 词、已完成数量、待复习数量。
3. 较小入口：`Testa il tuo vocabolario`。
4. 继续上次未完成训练或诊断的入口，仅在存在中断记录时显示。
5. 一张推荐阅读卡，说明其与已学词的匹配度，但不提前解释文章生词。

点击“开始练习”后，系统直接依据设置和学习记录组题，不再出现题型选择页。

### 4.2 阅读页

阅读列表允许按 CEFR 和主题筛选。主题首批集中在：工作、商业、科技、设计、项目协作和米兰职场生活。

文章详情按以下顺序呈现：

1. 标题、来源、等级、预计时间。
2. 完整文章或合规摘录。
3. 阅读理解题。
4. 提交后反馈：正确答案、原文证据、同义替换、推理过程和可打开的词汇节点。

提交前不显示词义气泡、行内中文翻译或“生词表”。

### 4.3 词库页

- **已学词**：按 CEFR、掌握状态、词性、主题和最近复习时间筛选。
- **错题**：保留原题、用户答案、正确答案、错误原因和关联词。
- **短语**：固定搭配、介词结构、习语和多词表达。

任何词汇详情页都可以打开相关词；浏览器内部维护返回路径，使学习者能从 `tenere` 打开 `tenere a`、再打开近义词后返回原节点。

### 4.4 设置页

只有设置页可以改变：

- 目标 CEFR：A1、A2、B1、B2、C1、C2 或“根据诊断推荐”。
- 启用的题型。
- 每日目标，默认 20 个目标词。
- 是否显示答题后的中文解释。
- 是否允许少量高一级的挑战词。
- 本地数据导出、导入和清除。

## 5. 共享内容架构

GitHub 仓库保存公开、版本化的学习内容。首版采用分文件 JSON，不建立一个不断膨胀的总文件。

`chenpihuamei/italiano-flow` 成为公开应用代码、共享内容和规格的规范来源；本地 Project_009 继续保存个人学习档案、过程证据和不应公开的材料。公开站必须能仅凭 GitHub 仓库完成构建，不能依赖未提交的私人文件。发布前另做隐私扫描，防止本地内容被带入公开构建。

```text
data/
  lexicon/
    manifest.json
    a1.json
    a2.json
    b1.json
    b2.json
    c1.json
    c2.json
  readings/
    manifest.json
    a1.json
    a2.json
    b1.json
    b2.json
    c1.json
    c2.json
  diagnostic/
    manifest.json
    items.json
    reference-bands.json
  schemas/
    lexeme.schema.json
    reading.schema.json
    diagnostic-item.schema.json
```

`manifest.json` 记录内容版本、发布日期、文件哈希、数量、引用来源和兼容的应用版本。所有跨节点关系使用稳定 ID，不使用容易变化的数组下标或显示文本。

## 6. 词汇节点模型

每个词汇节点至少包含：

```json
{
  "id": "it-tenere-v-001",
  "lemma": "tenere",
  "partOfSpeech": "verb",
  "cefr": "B1",
  "levelEvidence": [
    {
      "sourceId": "source-id",
      "label": "B1",
      "confidence": "medium"
    }
  ],
  "senses": [],
  "forms": [],
  "collocations": [],
  "phrases": [],
  "morphology": {
    "root": null,
    "prefixes": [],
    "suffixes": [],
    "familyIds": []
  },
  "relations": {
    "synonymIds": [],
    "antonymIds": [],
    "lookalikeIds": [],
    "confusableIds": [],
    "relatedIds": []
  },
  "examples": [],
  "exerciseRefs": [],
  "sourceRefs": []
}
```

### 6.1 义项

每个 `sense` 独立记录：

- 意大利语释义。
- 可选中文解释，只在反馈阶段显示。
- 语域：中性、正式、口语、粗俗、书面、专业等。
- 地域信息：仅在有可靠证据时记录；标准意大利语不强行标注地区。
- 常见结构和支配介词。
- 频率或教学优先级。
- 关联例句和题目。

### 6.2 形态和变位

`forms` 只保存教学需要或不规则的形式，以及可生成形式的规则引用。每道变位题必须绑定：

- 目标 lemma 和义项。
- 人称、数、时态、语气和语态。
- 该语境中为什么选择此形式。
- 可接受答案列表及重音、大小写、撇号规范化规则。

### 6.3 例句

每个首版词汇节点至少提供三个完整例句：

1. 最常见的核心语境。
2. 不同结构、时态或语气下的自然变体。
3. 职场、商业、科技或设计语境中的应用。

若词汇有显著不同义项，每个首批开放义项至少有一个独立例句。例句不得仅通过机械替换主语制造数量。

### 6.4 关系的双向一致性

如果 A 把 B 标记为近义、形近或易混词，构建校验必须确认 B 存在，并能返回 A。方向性关系需要显式声明，例如“B 是 A 的派生词”可以使用不同的正反向关系类型。

## 8. 训练系统

### 8.1 每日队列

默认训练单元围绕 20 个目标词生成。优先级依次为：

1. 到期复习且曾答错的词。
2. 阅读中暴露的薄弱词。
3. 已学但尚未通过语境题的词。
4. 当前目标等级的新词。
5. 设置允许时，少量高一级挑战词。

一个词不会在第一次出现时展示全部材料。它沿以下阶段推进：

`认识词义 → 核心语境 → 搭配/短语 → 词形变化 → 易混辨析 → 主动回忆`

答错的词在同一训练后段再次出现，但题面和例句必须变化，避免只记住答案位置。

### 8.2 题型

- 选择释义：意大利语释义，包含 `Non lo so`。
- 形近词辨析：干扰项必须来自真实形近词或易混词，不允许无意义随机项。
- 情境挖空：根据完整句子选择 lemma 或短语。
- 变位/词形：输入最自然的时态、语气、数、性或派生形式。
- 语境义：同一表面词在不同句子中的意义变化。
- 搭配与短语：介词、固定搭配和多词表达。
- 同义改写：用语义相近但结构不同的表达完成句子。

设置关闭某题型后，组题器只能选择仍启用且该词具有有效素材的题型。若可用题型不足，应用显示明确说明，不偷偷恢复已关闭题型。

### 8.3 掌握状态

每个词在设备上具有以下状态：

- `unseen`：未学习。
- `learning`：已接触但尚未通过语境验证。
- `review`：进入间隔复习。
- `weak`：近期错误或长时间未成功回忆。
- `mastered`：在不同题型和不同日期达到标准。

“掌握”要求至少跨两个日期、通过两种不同题型，其中一种必须是语境或主动输入题；单次选择正确不能直接标记为掌握。

## 9. 自适应词汇诊断

### 9.1 题库和流程

首版诊断题库约 120 题：

| CEFR | 题数 |
| --- | ---: |
| A1 | 12 |
| A2 | 14 |
| B1 | 20 |
| B2 | 28 |
| C1 | 30 |
| C2 | 16 |
| **合计** | **120** |

每次测试抽取 45–60 题，包含两个维度：

- **接受性识别**：词义、同义替换、核心搭配。
- **语境运用**：语境挖空、词形、短语选择、指代或改写。

测试语言全部为意大利语。每题始终提供 `Non lo so`；选择它按错误计分，但不会附加猜测惩罚。测试可以中断并在同一设备继续。

第一阶段使用跨等级锚点定位大致区间，第二阶段在边界等级加密抽题。连续成功会向上探测，连续错误或 `Non lo so` 会向下确认。规则、停止条件和版本写入 `diagnostic/manifest.json`，使同一版本的结果可复现。

### 9.2 三个结果

诊断报告同时显示：

1. **接受性词汇估计**：相对于明确标注版本的参考词表，显示词数区间而不是单一精确数字。
2. **语境运用分数**：0–100，并分解为语义、搭配和词形表现。
3. **综合有效词汇估计**：结合识别和语境表现得到的词数区间、建议 CEFR 与置信度。

每个 CEFR 层级在 `reference-bands.json` 中保存参考词表规模 `N_l`、来源和版本。对层级 `l`：

- `p_rec,l = (接受性正确题数 + 1) / (该层接受性作答数 + 2)`。
- `p_ctx,l = (语境正确题数 + 1) / (该层语境作答数 + 2)`。
- 接受性词汇点估计为 `Σ N_l × p_rec,l`。
- 语境运用分数为已充分抽样等级中 `p_ctx,l` 按 `N_l` 加权后的百分制结果；未被抽样的等级不参与分母。
- 有效掌握率使用 `sqrt(p_rec,l × p_ctx,l)`，避免单靠猜中释义得到过高综合估计。
- 综合有效词汇点估计为 `Σ N_l × sqrt(p_rec,l × p_ctx,l)`。

只有在某等级的两个维度都至少作答三题时，才计算该等级的点估计；否则该等级显示“样本不足”，不进入总量。区间使用各层二项比例的 Wilson 80% 区间传播得到。页面必须明确写明：这是针对指定参考词表的学习诊断，不是完整意大利语词汇量的精确测量，也不是正式 CEFR 认证。

首版使用透明规则法。只有积累足够匿名且获授权的真实答题数据、完成题目难度校准后，才考虑 IRT；本版本不上传答题数据，因此不实施 IRT。

## 10. 阅读系统

### 10.1 文章匹配

首版阅读采用预先编写并人工复核的文章库，不在浏览器中随机生成文章。推荐算法使用本地学习记录匹配：

- 文章约 80%–90% 的核心词应为已学或目标等级内的词。
- 优先包含近期薄弱、到期或刚学过的词。
- 每篇只允许少量高一级挑战词。
- 如果没有达到覆盖阈值的文章，显示最接近的文章及实际覆盖率，不伪称“完全个性化”。

### 10.2 文章数据

每篇文章至少包含：

- 稳定 ID、标题、CEFR、主题、字数和预计时间。
- 正文或合规摘录。
- 目标词 ID、逻辑连接词、短语和代词/省略结构。
- 预期已学覆盖率计算规则。
- 题目、答案、证据位置、同义替换和解释。
- 完整版权状态和来源记录。

### 10.3 阅读题型

题目借鉴 IELTS 的能力维度，但不复制 IELTS 原题：

- 主旨与标题选择。
- 细节的同义替换。
- 短语在上下文中的意义。
- 代词、指示词和省略成分的指代。
- 推断和隐含意义。
- 作者态度与逻辑关系。
- `Vero / Falso / Non indicato`。

答题反馈必须指出证据句，并解释题干怎样改写原文。不能只显示红绿状态。

### 10.4 首版文章数量

| A1 | 1 |
| A2 | 2 |
| B1 | 3 |
| B2 | 5 |
| C1 | 5 |
| C2 | 2 |
| **合计** | **18** |

## 11. 版权和来源模型

非盈利、小范围传播或不修改原文都不自动构成复制全文的许可。GitHub 公开仓库和 GitHub Pages 按公开传播处理。

每篇文章必须包含：

```json
{
  "rights": {
    "status": "original",
    "sourceUrl": null,
    "title": null,
    "author": null,
    "publisher": null,
    "license": null,
    "attribution": null,
    "permissionEvidence": null,
    "excerptPurpose": null,
    "reviewedAt": "2026-09-19"
  }
}
```

允许的 `status`：

- `original`：项目原创全文。
- `public-domain`：公版全文，记录依据和来源。
- `cc`：开放许可全文，遵守具体许可证和署名要求。
- `licensed`：获得明确授权的全文，记录许可证据但不公开敏感合同。
- `excerpt`：为分析或教学所需的合理短摘录，必须有出处、链接和使用理由。
- `link-only`：只保存元数据、题目设计和外部链接，不在仓库保存正文。
- `user-local`：用户在自己设备导入的合法材料，只能存在 IndexedDB，禁止进入公开构建。

公开构建必须失败的情况：

- 缺少 `rights` 或状态未知。
- `link-only` 项目包含正文。
- `user-local` 内容出现在仓库数据中。
- `excerpt` 缺少来源链接、署名或教学目的说明。
- `cc` 缺少许可证和署名字段。
- `licensed` 缺少内部许可证据引用。

自动检查只能验证记录完整性，不能判断摘录长度在所有情境下是否合法；`excerpt` 仍需人工复核。首版不设一个虚假的通用“安全字数”。

`link-only` 阅读卡会在新标签页打开出版社原文，应用保留返回后的答题状态；题目不得通过连续引用重新拼出原文。

## 12. 本地数据和隐私

应用使用 IndexedDB 保存：

- 用户设置。
- 词汇掌握状态和复习日期。
- 答题事件和错题。
- 阅读答题记录。
- 诊断测试过程和历史结果。
- 用户本地导入内容。

公共内容和个人状态通过稳定 ID 关联。内容更新时，旧 ID 不得复用给不同词或文章。

### 12.1 旧数据迁移

首次运行新版时：

1. 检测现有 Italiano Flow 的 `localStorage` 键。
2. 把可识别的训练记录复制到 IndexedDB。
3. 验证写入数量和关键字段。
4. 标记迁移版本，但暂不删除旧数据。
5. 用户完成一次正常启动并可导出后，后续版本才允许清理旧键。

迁移失败时继续使用旧数据并显示说明，不得静默重置用户进度。

### 12.2 降级策略

- IndexedDB 不可用：暂时使用受限的 `localStorage`，同时提示无法保存本地导入长文本。
- 浏览器存储完全不可用：允许临时练习，但明确提示关闭页面后记录会丢失。
- 不向任何远程服务器发送个人答题记录。

## 13. 数据流

### 13.1 训练

```text
设置 + 本地掌握状态 + 公共词库
  → 队列选择器
  → 题目生成器选择已有、已审核素材
  → 用户作答
  → 规范化与判分
  → 反馈和关联词
  → IndexedDB 更新掌握状态与错题
```

### 13.2 阅读

```text
用户目标等级 + 已学词/弱词
  → 文章匹配和覆盖率计算
  → 无词义提示的正文
  → 阅读理解题
  → 提交
  → 证据、同义替换、解释和词汇链接
  → IndexedDB 更新阅读记录与薄弱词
```

### 13.3 诊断

```text
跨等级锚点
  → 规则路由到相邻等级
  → 45–60 题响应
  → 分层识别率与语境率
  → 三项结果 + 置信度 + 建议等级
  → 用户接受或覆盖建议
```

## 14. 错误处理

- 公共数据加载失败：先尝试当前 Service Worker 缓存，再提供重试和离线说明。
- 数据版本不兼容：不混合新旧结构，保留本地记录并提示升级恢复步骤。
- 关系指向不存在：在构建阶段失败，不把坏链接发布到线上。
- 诊断中断：保存题序、已答项目和算法版本；恢复时不重新抽题。
- 内容更新后题目被移除：历史错题保留快照，并标记原题已退役。
- 用户输入的重音、大小写和撇号：先按意大利语规范化规则比较，再区分拼写错误和目标语法错误。
- Service Worker 更新：使用版本化缓存，完成当前训练后再提示刷新，避免半途中切换题库。

## 16. 成功标准

重构完成必须同时满足：

1. 首屏只有明确的训练主行动，用户一次点击进入练习。
2. 导航只保留训练、阅读、词库、设置；资源、字幕和独立进度入口消失。
3. 600 词数据达到规定的等级比例，且每个词是可关联、可训练的节点。
4. 诊断在 45–60 题内输出接受性词汇、语境分数和综合有效词汇估计，并说明参考版本和置信度。
5. 阅读推荐确实使用本地已学词记录计算覆盖率；答题前不显示词义。
6. 已学词、错题和短语可以检索，关联词可以互相打开。
7. 当前用户已有本地记录不会因升级被静默清除。
8. 所有公开阅读材料都有明确权利状态，构建检查能阻止未知或不允许公开的正文。
9. 所有个人进度仍只在设备本地，公开仓库不包含用户个人资料或本地导入文本。
10. 自动测试、三档浏览器 QA、离线验证和 GitHub Pages 发布检查全部通过后才能替换线上版本。

## 17. 实施边界和里程碑

本设计作为一个产品重构实施，但按可独立验证的里程碑推进：

1. **基础迁移**：新信息架构、IndexedDB、旧数据迁移、内容 schema 和构建校验。
2. **诊断**：120 题题库结构、自适应规则和三项结果。
3. **词库**：600 词节点、关系、例句和来源审计。
4. **训练**：20 词队列、多题型、掌握状态、错题闭环。
5. **阅读**：18 篇文章、匹配算法、IELTS 风格能力题和反馈。
6. **发布**：完整自动验证、移动端浏览器 QA、旧版迁移复核和 GitHub Pages 替换。

每个里程碑必须保留可运行状态。内容数量不足时不能用临时虚构词条、空例句或重复模板冒充完成。

## 18. 已确认决策摘要

- 产品只聚焦词汇与阅读。
- 首版先做诊断，再据结果微调 600 词的实际选择。
- 600 词主要集中 B2–C1，但保留 A1–C2 诊断和训练覆盖。
- 测试以意大利语出题，中文只用于事后解释。
- 同时展示两个分项结果和一个综合词汇量估计。
- 题型选择只存在设置中。
- 阅读文章基于已学词匹配，答题前不解释生词。
- 公开内容进入 GitHub；个人学习记录进入 IndexedDB。
- 不建立账号和云同步，朋友使用各自设备的独立进度。
- 公开阅读采用“授权全文 + 合理短摘录 + 外链 + 本地私人内容”的版权分层。
